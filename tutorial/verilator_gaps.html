DPI-C from scratch · Reference

What doesn't work (or works differently) in Verilator 5.052

Every DPI-C behavior in this tutorial where Verilator 5.052 departs from the LRM, from commercial simulators, or from what the book assumes, in one place. Nothing here is from memory: each row links to the step and the lab file that measures it (check.py asserts it, or NOTES.md records the measurement).

The 10 that will bite you

Silent wrong results first: a build error costs you a minute, a silent one costs you a tape-out review.

  1. Outputs C never writes come back as garbage — silent wrong result.
  2. Missing context can call the wrong instance — silent wrong result.
  3. shortreal is passed as double — silent wrong result.
  4. X and Z arrive in C as 0 — silent wrong result.
  5. --threads: DPI runs on other OS threads — silent wrong result.
  6. Without the generated header, a parameter mismatch links silently — silent wrong result.
  7. pure is never exploited — silent wrong result.
  8. $error aborts at the first error, and final blocks don't run — aborts / crashes at run time.
  9. Dynamic arrays and queues can't be open-array actuals — breaks the build.
  10. No timing controls in exported tasks — breaks the build.

Three habits remove most of this page: include Vtop__Dpi.h in every C file, write every output on every path, and run with +verilator+error+limit+N. The rest are portability notes: code that passes here can still break on Questa, VCS or Xcelium, mostly because Verilator is 2-state and more forgiving with illegal code.

just different · implementation-defined		The LRM does not guarantee zeroed unused bits on input, nor masking on output.Inputs arrive with zero unused bits and no sign extension; output copy-back masks to the declared width (VL_SET_Q_SVBV(40, …), scalars 1U & x). just different · implementation-defined		Unspecified by the LRM.Two always blocks calling the same import at the same time: the second-declared instance ran first (u2 before u1). final: top's ran before the instances' (u2, then u1).Never depend on it; free shared C state in one place.03 · static_counter.sv
